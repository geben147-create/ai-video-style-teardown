대본 엔진은 A+B+C+D 방식으로 잠근다

A · 큰 구조

B · 말의 연결

질문 → 부분 답 → 새 질문을 반복해 정보가 끝나지 않고 앞으로 미끄러지게 만든다.

C + D · 화면과 TTS

C처럼 막 전환·장면 회수를 설계하고, D처럼 한 문장 한 정보로 TTS를 짧게 자른다.

멀티 에이전트 역할 8개

1. ORCHESTRATOR

프로젝트 상태를 관리하고 다음 단계로 넘긴다. 동일 오류 2회면 자동 중단하고 사람 검수를 요청한다.

2. RESEARCHER

최신·공식·학술 자료를 수집한다. 모든 claim에 source_url, date, confidence를 붙이고 미확인은 미확인으로 남긴다.

3. STORY ARCHITECT

중심 질문 1개, open loop 2~4개, 30~45초마다 micro-payoff를 배치한다. 투자 연결은 역사/과학 몰입을 깨지 않는 후반부로 제한한다.

4. VISUAL DIRECTOR

한 장면=한 아이디어. 항공·POV·cutaway·X-ray·map morph를 의미가 있을 때만 선택한다.

5. CONTINUITY SUPERVISOR

얼굴, 의상, 손, 소품, 화면 방향, 날씨, 렌즈, 광원과 state_in/out을 잠근다.

6. PROMPT COMPILER

정지 이미지의 구성 지시와 영상의 움직임 지시를 분리한다. 한 클립에 카메라 1동작 + 피사체 1행동 원칙.

7. EDITOR PLANNER

문장/단어와 컷을 맞추고 SFX·BGM ducking·자막을 초 단위로 만든다. 통과 전환은 클립 경계에서 우선 사용.

8. QA + PACKAGING

팩트, 과장, 시각 중복, 리텐션, 썸네일·제목 약속 불일치를 체크한다. NOW 성과와 Evergreen 성과를 별도 평가한다.

Visual Evidence Map → Shot Contract

{
  "scene_id": "S023",
  "time": "03:42-03:50",
  "narration": "길 하나가 아니라 거점이 네트워크를 살렸다.",
  "visual_claim": "route nodes matter more than a single line",
  "evidence": ["map_source_01", "paper_figure_02"],
  "shot_type": "top_down_map_to_3d",
  "camera_move": "slow push-in",
  "subject_action": "route nodes illuminate sequentially",
  "state_in": {"direction":"L2R","light":"sunset","prop":"red_route_line"},
  "state_out": {"direction":"L2R","coverage":"cloud_wipe_95%","next_ready":true},
  "duration_sec": 8,
  "overlay_post_only": ["distance", "year", "source label"]
}

핵심은 마지막 프레임이 다음 클립의 첫 프레임이 될 수 있게 state_out을 미리 설계하는 것이다. 생성 모델에게 ‘예쁘게 끝내라’가 아니라 ‘다음 액션이 가능한 상태로 끝내라’고 지시한다.

생성 예산과 승인 순서

Gate 1 · Hero 10

전체 70~100컷을 만들기 전에 가장 어려운 10컷만 만든다. 캐릭터, 건축, X-ray, 대형 항공, 전환 컷을 반드시 포함.

Gate 2 · Acceptance

별책의 공개 사례 채택률은 대략 3.8~14.2% 범위였다. 이를 품질 보증값이 아니라 예산 스트레스 테스트로만 사용한다.

Gate 3 · Expand

Hero 10이 통과한 스타일·캐릭터·렌즈·색·transition whitelist만 전체 씬으로 확장한다.

🟢 QC

자동 검수 체크리스트

  • 제목의 약속이 첫 30초와 본문에서 회수되는가
  • 모든 사실 claim에 근거가 있는가
  • 미확정 사건을 성공/실패로 단정하지 않았는가
  • 30~45초마다 질문/부분 보상이 있는가
  • 한 장면에 설명 2개 이상 들어가 있지 않은가
  • 한 영상 클립에 카메라 동작 2개 이상 강제하지 않았는가
  • 캐릭터 얼굴 정면 노출이 예산을 넘지 않는가
  • 인물/의상/소품/스크린 방향이 이어지는가
  • state_out과 다음 state_in이 호환되는가
  • 오버레이 텍스트는 이미지 생성이 아니라 후편집인가
  • 스펙터클 피크가 너무 자주 반복되지 않는가
  • 후반 투자 연결이 본문 근거에서 자연스럽게 도출되는가
  • 특정 주식 추천처럼 읽히지 않고 판단 지표를 제공하는가
  • CTA가 영상의 중심 질문을 그대로 연장하는가

[작업 순서]
1. 자료조사 전에 중심 질문 1개와 검증해야 할 주장 목록을 만든다.
2. 공식 1차자료 → 논문/기관 → 신뢰보도 순으로 Research Pack을 만든다.
3. 각 claim에 source/date/confidence/counterpoint를 붙인다. 확인되지 않은 것은 추정으로 분리한다.
4. 대본은 A의 큰 구조 + B의 질문→부분답→새질문 + C의 장면 회수 + D의 한문장 한정보를 따른다.
5. 8단계 Harmon Circle을 사용하되 30~45초마다 micro-payoff를 둔다.
6. 각 대사 1~2문장마다 visual_claim을 만들고 실제 자료가 있으면 우선 사용한다.
7. STYLE_PROFILE을 잠그고 character/background/prop bible을 만든다.
8. 먼저 Hero 10 storyboard만 생성한다. 내가 승인하기 전 전체 씬으로 확장하지 않는다.
9. 정지 이미지 프롬프트와 영상 모션 프롬프트를 분리한다.
10. 영상 프롬프트는 one camera move + one subject action만 허용한다.
11. 모든 씬에 state_in/state_out을 작성해 다음 씬과 연결한다.
12. 이미지 내부 텍스트 생성은 금지하고 수치·자막·지도 라벨은 후편집용 overlay로 분리한다.
13. 최종 산출물: Research Pack / Script / TTS / Visual Evidence Map / Asset Bible / Storyboard / Image Prompts / Video Prompts / Edit Timeline / QC Report / Publish Pack.

[중단 규칙]
- 동일한 생성 오류 2회 반복
- 출처 충돌이 해결되지 않음
- 캐릭터/장소 continuity가 Hero 10에서 실패
- 제목 약속과 대본 결론이 불일치
위 조건이면 자동 확장하지 말고 RED FLAG를 출력한다.
