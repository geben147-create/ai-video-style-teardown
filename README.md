# AI 역사 다큐 영상 제작 원리 해부

[**▶ 분석 보고서 (17절)**](https://geben147-create.github.io/ai-video-style-teardown/) · [**▶ 캡처 갤러리**](https://geben147-create.github.io/ai-video-style-teardown/gallery.html)

완성된 롱폼 영상 1편을 프레임 단위로 전수 계측해, **다른 주제에도 그대로 이식할 수 있는 제작 규격서**로 되돌린 자료입니다.
측정값·캡처·시계열 원본·분석 스크립트를 전부 포함했습니다.
보고서의 모든 수치는 공개된 원시 덤프와 결과 JSON 으로 검산할 수 있습니다. 다만 파이프라인 전체를 처음부터 다시 돌리는 것은 이 저장소만으로는 불가능합니다 — 이유는 [재현되지 않는 부분](#재현되지-않는-부분--솔직하게)에 그대로 적어 뒀습니다.

- **분석 대상** — 딥 호라이즌 「잉카 문명은 왜 멸망했나?」 · 19분 29초 · 1280×720 · 60fps
- **측정 규모** — 프레임 70,134장 전수 계산 · 10fps 시계열 11,689 샘플 · 경계 98개 육안 전수 검증
- **측정일** — 2026-09-05 (유튜브 공개 지표는 2026-09-06 재확인: 조회 52.1만 / 좋아요 7,373 / 댓글 313)

분석 대상은 채널 운영자 본인의 제작물입니다. 외부 영상을 뜯어본 것이 아니라, **이미 만든 결과물을 수치로 되돌려 재사용 가능한 규격으로 만든 것**입니다.

## 핵심 발견 3가지

### 1. 통과 전환이 전환의 25.4%다

카메라가 구름·아치·말 몸통 같은 차폐물 **속으로 들어가 화면이 100% 덮이는 순간**에 컷을 바꿉니다.
서로 다른 시드에서 나온 AI 클립 두 개를 이어붙이는 문제를, **이어붙일 정보 자체를 없애서** 해결한 구조입니다.
차폐물만 바꾸면 어떤 주제에도 이식됩니다 — 연기·물보라·터널·깃발·지나가는 차.

### 2. 난색 픽셀 비율 하나가 서사를 끌고 간다

황금기(5~9분) 36.6~56.9%(중앙값 51.7) → 몰락기(10~15분) 7.8~19.7% → 유산(16분) 56.9% 회복.
황금기 5개 구간 중 7분만 36.6%로 예외다(마추픽추 청록 구간).
개별 컷이 평범해도 이 곡선만 지키면 영상 전체가 감정을 갖습니다.
구현은 구간별 광원 지시 한 줄입니다 — 황금기 `warm golden hour`, 몰락기 `cold overcast, blue hour`.

### 3. 얼굴 노출 예산은 러닝타임의 5% 미만

이름 있는 인물의 정면 얼굴 컷은 19분 동안 5회, 합계 약 25초(2%)다.
이름 없는 일반인 얼굴이 보이는 두 구간(8:01~8:24 군중·식사, 16:33~16:37 가족)을 더해도 약 51초(4.4%)에 그친다.
나머지는 머리 자르기 · 사물 인서트 · 후면 샷 · 실루엣 · 모션 블러 · 극소형 배치 · 양식화 초상으로 처리합니다.
AI 영상의 최대 실패 지점을 **화면에 넣지 않는 방식**으로 회피합니다.

## 파이프라인 재실행

**필요한 것** — Python 3.9+ · ffmpeg · yt-dlp 2026.08.19 이상 · `pip install numpy pillow`

`rgb.py` 와 `cuts.py` 는 환경변수 `SP` 를 작업공간 루트로 읽고, 중간 산출물을 모두 `$SP/an/` 에 쓴다.
나머지 스크립트는 **현재 폴더 기준 상대 경로**로 동작하므로 `$SP/an` 안에서 실행한다.

```bash
# 0) 작업공간
export SP=/path/to/workspace          # Windows: set SP=C:\path\to\workspace
mkdir -p "$SP/an" && cd "$SP/an"

# 1) 영상 받기 (구버전 yt-dlp 는 403)
yt-dlp -o video.mp4 --write-auto-subs --sub-langs "en.*" \
  "https://www.youtube.com/watch?v=ncfT8EvuX24"

# 2) 10fps RGB 시계열  → $SP/an/rgb.npy (182MB)
python <repo>/pipeline/rgb.py video.mp4

# 3) 씬 점수 · 휘도 원시 덤프 → $SP/an/ 에 직접 쓴다
ffmpeg -i video.mp4 -an -vf \
  "scale=192:108,scdet=s=0:t=10,metadata=mode=print:key=lavfi.scd.score:file=$SP/an/scd.txt" -f null -
ffmpeg -i video.mp4 -an -vf \
  "scale=64:36,signalstats,metadata=mode=print:key=lavfi.signalstats.YAVG:file=$SP/an/yavg.txt" -f null -

# 4) 컷 검출 (영상 파일 불필요 — 3단계 덤프만 읽는다)
python <repo>/pipeline/cuts.py

# 5) 보고서 조립 — 반드시 이 순서
cp <repo>/data/metrics.json     data.json
cp <repo>/data/charts_svg.json  charts.json     # gen_head.py 를 다시 돌리면 재생성됨
cp <repo>/data/scenes_verified.json .
python <repo>/pipeline/gen_head.py              # charts.json
python <repo>/pipeline/gen_a.py                 # _css.txt · _nav.txt · _fig.json
for i in 1 2 3 4 5; do python <repo>/pipeline/body$i.py; done
python <repo>/pipeline/assemble.py              # index.html
```

**ffmpeg 주의** — 최신 빌드에서 `-vsync` 가 제거됐다. `-fps_mode passthrough` 를 쓴다.
프레임 추출에 `-vsync` 를 쓰는 도구는 `Unrecognized option 'vsync'` 로 중단된다.

### 재현되지 않는 부분 — 솔직하게

이 저장소의 `pipeline/` 은 **정리된 파이프라인이 아니라 작업 당시 실행한 스크립트 원본**이다.
아래는 코드가 남아 있지 않아 그대로는 재현되지 않는다.

| 산출물 | 상태 |
|---|---|
| `data/detection_pass1_196.json` | 1차 검출 코드가 세션 내 임시 실행분이라 남아 있지 않다. 공개된 `cuts.py` 는 **다른 임계값**의 초기 버전이라 같은 덤프를 먹여도 196개가 나오지 않는다 |
| `data/metrics.json` · `palette.json` · `camera.json` · `scenes_verified.json` | 측정 코드가 세션 내 임시 실행분이라 생산자 스크립트가 없다. 결과 JSON 은 전부 공개돼 있으므로 **검산은 가능하지만 재생성은 안 된다** |
| `data/timeseries/timeseries_10fps.csv` | `stage2.py` 가 `.npy` 들을 합쳐 만든다. `.npy` 자체를 만드는 측정 코드는 위와 같은 이유로 없다 |
| `gen_a.py` 가 읽는 `fig/` 16장 | 저장소 파일명과 다르고 12장은 축소본이다. 축소 스크립트도 남아 있지 않다 |

즉 **보고서의 수치는 전부 검산 가능하지만(원시 덤프·시계열·결과 JSON 공개), 파이프라인을 처음부터 다시 돌리는 것은 이 저장소만으로는 불가능하다.**
이 한계를 감추지 않기 위해 스크립트를 그대로 공개했다.

용량 때문에 넣지 않은 것 — 원본 영상(196MB), `rgb.npy`(182MB), `feat.npy`(27MB). 앞 두 개는 위 1·2단계로 재생성된다.

## 정확도 — 숨기지 않았습니다

| 항목 | 값 |
|---|---|
| 자동 검출 후보 | 98개 |
| 육안 판독 | 98개 전부 (100%) |
| 정탐 / 오탐 | 71 / 27 → **정밀도 72.4%** |
| 누락 점검 | 15초 이상 장면 25개 내부를 4초 간격 218컷으로 재판독 |
| 누락 확인 | **약 45개 경계** |

그래서 장면 수를 **확정 72개(하한)** 와 **추정 약 115개** 두 숫자로 병기합니다.

1차 자동 검출 196개는 표본 14개 중 13개가 "연속 카메라 이동 중의 변화"였음이 확인돼 폐기했습니다
(`data/detection_pass1_196.json` 에 원본을 남겨 뒀습니다).
팔레트가 균일하고 카메라가 항상 움직이는 영상에서는 씬 점수·노벨티 단독 검출이 무너집니다.
**경계 전후 프레임 쌍의 육안 검증이 필수입니다.** 자세한 내용은 17절에 있습니다.

## 측정 방법

| 지표 | 방법 |
|---|---|
| 컷 후보 1차 | ffmpeg `scdet` 전 프레임 씬 점수 (70,134) |
| 컷 후보 2차 | 3×3 공간 분할 컬러 히스토그램(576차) 자기유사도 노벨티 |
| 장면 확정 | ±0.5초 스트래들 히스토그램 거리 + 그래디언트 선명도 저하율 |
| 전환 유형 | 휘도 최소/최대 + 공간 그래디언트 에너지 저하율 |
| 카메라 무브 | 연속 프레임 위상상관 누적 변위 + 방사 에너지 반경비 |
| 색 | 170만 픽셀 표본 k-means 10색 + 전 프레임 난색/한색 판정 |
| 사운드 | 16kHz 모노 변환 후 0.1초 RMS + 스펙트럴 센트로이드 |
| 레이아웃 | 1280×720 원본 38장에서 고휘도 픽셀의 행/열 분포 |

## 범위

- **숫자는 측정값**입니다. 원본 영상 파일을 직접 디코딩해 계산했습니다.
- **"왜 그렇게 했는가"는 해석**입니다. 완성된 화면에서 거꾸로 읽은 것이라 제작 당시 의도와 다를 수 있습니다. 다만 다른 주제에 이식할 때 필요한 것은 의도가 아니라 화면에 실제로 남은 규칙이므로, 측정값 기준으로 서술했습니다. 확정 사실과 해석은 17절에서 분리했습니다.
- 영상에 쓰인 배경음악이 외부 라이선스 음원이라면 그 부분의 재배포 조건은 별도 확인이 필요합니다. 이 저장소에 오디오 파일은 없고 라우드니스·스펙트럼 수치만 있습니다.
